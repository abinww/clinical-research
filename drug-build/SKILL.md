# 创新药建库编排

## 责任与边界

- 由 `clinical-research/SKILL.md` 路由后执行，为指定创新药编排身份锚定、临床管线、数据搜索、提取、验证和完整索引归档。
- 固定顺序为：身份锚定 → 管线 → 候选临床 → 选择或自动全选 → 选中试验的最佳来源 → 可续跑 plan → 按状态恢复 → 复查全部索引维度。
- 不重复实现子 skill 内部逻辑；读取并执行对应 `SKILL.md`。除非用户明确要求，不跳步。
- 多链接提取、验证与索引由 `multi-extractor` 内部处理，每轮最多 5 个并发子 agent（或 harness 允许的上限；OpenClaw 默认 `maxChildrenPerAgent=5`）；本 skill 只按状态分组和精确派发。
- 静默执行；仅在身份无法确认、plan 为空、出现歧义、选中试验无法解析来源或缺少用户选择时停下。首次建库必须在检索来源前确定纳入的临床试验：去重后 1–5 个自动全选，6 个及以上必须让用户多选，0 个报告无候选并结束；plan 已有 `> 临床选择` 标记时续跑不重复询问（`待检索` 直接重跑来源检索）。用户选择 `none` 时结束本次建库，不进入提取。

## 输入与共享契约

第 1 步必须以 `mode: resolve_or_create` 调用 `../drug-identity/SKILL.md`，取得其定义的完整标准 identity/path context。后续子 skill 必须原样接收整个对象及绝对 `config_path`；不得摘取部分字段、删字段、改名或重算路径。兼容字段 `companies` 如存在，必须与 `company_ids` 相同。

plan 文件名格式为：

```text
"{research_dir}/.temp/plans/search_plan_{drug_id}_{date}.md"
```

canonical source 保持提取体系的准确值：URL 不改写大小写、查询参数、尾斜杠或编码；本地 PDF 使用持久化身份（`<= 10 MiB` 附件化后为附件绝对路径 `attachments/{drug_id}@{source_label}.pdf`，`> 10 MiB` 为 resolved absolute POSIX path）。plan 内按 canonical source 准确字符串合并；库内判重只限当前 `drug_id`，其他药品可合法复用同一来源。

开始本次建库前，先扫描 `.temp/plans/search_plan_{drug_id}_*.md`：恰有一个未完成 plan 时继续使用其绝对路径；多个匹配时停止并请用户选择；没有匹配时才创建当天路径。下文 `{plan_path}` 指最终选定的绝对路径。

临床选择使用两阶段标记，均写在 plan 头部：

```text
> 临床选择: 待检索 {YYYY-MM-DD}（{自动全选|用户选择} X 个；已选: {试验 ID 列表}）
> 临床选择: 已确认 {YYYY-MM-DD}（{自动全选|用户选择} X 个 / 候选 Y；已选: {试验 ID 列表}）
```

- 选择确定后、调用 `resolve` 前，先在 `{plan_path}` 写入 `待检索` 标记，记录选择方式、数量和试验 ID；此时不得进入提取。
- 所有选中试验都已解析到来源（或用户明确同意跳过后）并写入 plan，才改写为 `已确认`。
- `待检索` 表示续跑时不再询问选择，直接按标记中的试验 ID 重新执行 3.3；自动全选与用户多选续跑行为一致。
- 标记只表示选择范围和来源检索进度，不表示抓取或索引已完成。

进度检查必须使用以下绝对路径命令，不得改变：

```text
python "{clinical_research_dir}/drug-build/scripts/check_plan_progress.py" --config "{clinical_research_dir}/config.yaml" --plan "{plan_path}" --company-id "{company_id}" --drug-id "{drug_id}"
```

## 不变量与写入策略

- `已完成` 等于 fully indexed：raw/summary、完整审核门禁、药品页、全部应建适应症页和根索引均完整。`verified_unindexed` 只表示 summary 已审核但 clinical-indexer 尚未完成，绝不是完成状态。只有主表全部行 `fully indexed` 且候选区为空时才删除 plan；候选区非空时保留 plan 并在输出注明。
- plan 尾部 `## 候选（未入库）` 列表区块存放用户未选择的临床试验，以及后续未入库的来源；候选区不参与进度检查、恢复与重试，行格式为列表而非表格。未选临床试验条目保留候选清单中的 ID、适应症/线、阶段、最近公开年月和未选原因，不写 URL；唯一例外是 `未命名-{n}` 条目需保留来源线索 URL，供续跑定位。
- 当前药品内已完整索引的重复来源静默跳过；其他药品中的相同来源不参与匹配，也不构成歧义。
- 续跑从当前持久状态恢复，不覆盖已有产物，不把未完成项整体重新提取。
- 可自动恢复的单项按当前状态重试一次，每项总尝试上限 2 次；第二轮后仍失败则保留 plan 并报告。
- 身份、当前药品内来源配对、路径或索引目标存在歧义时，停止该项自动恢复，不删除、覆盖或猜测。

以下是唯一规范的状态 → 动作 → 重试策略；流程第 5、6 步均引用此表：

| 脚本状态 | 规范状态 | 判定 | 精确动作 | 第 2 轮重试 |
|---|---|---|---|---|
| `未提取` | `unextracted` | 当前 `raw_dir` 无该 canonical source | `multi-extractor` 一次性处理该组 canonical source；内部完成提取、验证和部分索引 | 同动作精确重试一次 |
| `已提取未生成summary` | `raw-only` | 当前药品内唯一 raw、无 summary | `batch-extractor` 使用 `single_raw` 模式接收唯一 raw 绝对路径；禁止目录扫描 | 同动作精确重试一次 |
| `未审核` 或审核 pending/failed/incomplete | `pending/failed audit` | raw/summary 唯一，但未通过完整审核门禁 | `data-verify` 逐项接收唯一 summary 绝对路径；通过后立即交 `clinical-indexer` 部分模式，未通过则保留 plan | 同动作精确重试一次；通过后部分索引 |
| `已验证未索引` | `verified-unindexed` | 审核通过，但 clinical-indexer 尚未返回药品页、任一应建适应症页或根索引完整结果 | `clinical-indexer` 接收明确 summary 绝对路径列表执行部分模式；不得扩展扫描；等待其逐目标状态 | 同动作精确重试一次 |
| `已完成` | `fully indexed` | 审核和全部索引维度完整 | 跳过 | 不重试，完成 |
| `来源对应多个raw`、`一个raw对应多个summary`、`summary文件名不匹配`，或字段/路径冲突、错误索引引用、目标不唯一 | `ambiguity/manual` | 仅指当前公司级布局内歧义 | 不自动恢复；保留 plan，报告人工处理 | 不重试 |
| raw frontmatter、summary 来源链接或 managed 索引结构损坏 | `数据完整性错误` | 持久数据结构损坏 | 停止自动恢复；报告具体文件并保留 plan，禁止按“未提取”重抓 | 不重试 |

命令已传入 `company_id/drug_id`，因此 `来源对应多个raw` 只表示当前公司级布局异常。

## 流程

### 1. 锚定药品身份

按输入契约执行 `../drug-identity/SKILL.md`。无法确认身份时停下，请用户确认，不进入后续步骤。

### 2. 查询临床试验注册

读取 `../drug-trials-search/SKILL.md` 并执行其 workflow：查询该药品在 ClinicalTrials.gov 的全部试验，写入 identity 对象中 `drug_page` 的 `## 当前临床管线`；不创建 `trials/` 目录或独立 trial 搜索输出文件。

### 3. 候选临床、用户选择与最佳来源

#### 3.1 发现候选临床

先检查现有 plan 的 `> 临床选择` 标记，按状态分派：

- `待检索`：跳过候选发现和 3.2 询问，按标记中的试验 ID 直接进入 3.3。
- `已确认`：以 `discover` 模式取得候选清单，只用于补充未入库清单；跳过 3.2–3.3，直接进入第 4 步。
- 无标记：以 `discover` 模式取得候选清单并进入 3.2；旧 plan 主表已有试验必须并入候选清单（来源线索取该行 URL），避免旧行无法被选择。
- 旧 plan 带 `> 来源挑选:` 标记：按无标记处理，迁移时把原标记改成普通注释行，不沿用其选择结果。

候选清单由 `discover` 按 `data-search` 3.1 的纳入、归并和年月规则生成；本 skill 只原样展示，除并入旧 plan 已有试验外不自行增删。

候选清单只显示：

| # | 临床试验 | 适应症（含线） | 阶段 | 最近公开年月 |
|---|---|---|---|---|
| 1 | NCT06449222 / BNT327-02 | TNBC 1L/2L+ | II | 2026-11 |

不显示 URL，不展示来源比较结果。年月格式沿用 `discover` 的 `YYYY-MM` / `YYYY（月份未披露）` / “未披露”。无标记的首次建库遇到空清单时停止并报告“无临床候选”；已有 `已确认` 标记时只跳过候选补充，继续现有 plan。

#### 3.2 选择或自动全选

没有 `> 临床选择` 标记时，按去重后的候选试验数处理。计数前先应用用户已明确给出的排除条件：

- **0 个**：报告“无临床候选”并结束，不进入来源检索或提取。
- **1–5 个**：默认全部纳入，不询问用户。先列出纳入项供用户知情，再直接写入 `待检索` 标记（选择方式填“自动全选”）；这是告知，不等待确认。
- **6 个及以上**：必须等待用户多选，不得自动全选。

自动全选与用户多选使用同一后续流程，都必须完成 3.3 的来源检索和未解决门禁。

多选时使用以下规则：

- OpenCode：优先使用 `question` 工具的多选模式，label 用序号加试验 ID，适应症/线、阶段和年月放 description；控件无法展示这些详情或没有多选参数时，退回下面的编号文本。
- OpenClaw、WorkBuddy 或其他 harness：有复选或按钮控件且能展示全部字段时使用；否则输出上面的编号清单，等待文本回复。
- 文本回复接受 `1,3,5-7`、`all`、`none`，兼容中文逗号、顿号、空格和换行；解析后去重。
- 原生控件返回值必须映射回 3.1 的稳定编号或试验 ID，不得按显示文本模糊匹配。
- 无效序号、越界、空回复或无法解析时重新展示有效范围，不得自行猜测或默认选择。
- `none` 表示本次不纳入任何试验：结束建库，不进入来源检索或提取。
- 同一试验只允许出现一次；选项必须是 3.1 生成的稳定编号。
- 选项 ID 以 `discover` 返回的试验 ID 为准；`未命名-{n}` 必须原样传回，并同时传递其来源线索 URL 供 `resolve` 定位。
- 选择确定后，立即创建或复用 `{plan_path}`，在头部写入 `待检索` 标记（自动全选取“自动全选”，交互取“用户选择”）及选中 ID，并把完整候选清单写入候选区（未选项标注“未选择”；`未命名-{n}` 附来源线索 URL）；写入失败时停止，不进入 3.3。

#### 3.3 检索选中临床的最佳来源

选择确定后（自动全选或用户确认），以 `resolve` 模式再次调用 `../data-search/SKILL.md`，传入选中的试验 ID 清单；`未命名-{n}` 从 plan 候选区读取并附上来源线索 URL，缺失时停止。只为选中试验取回 plan 行；主链接的完整度、并列和备选判断由 `data-search` 3.2 定义，本 skill 不重复判定。

- 每个选中试验最多一行来源；已提取来源视为已覆盖，不重复写 plan 行，也不计入未解决项。
- 任一选中试验无法确定来源时，暂停 plan 提交和后续提取，列出未解决试验并等待用户决定重试或跳过；不得静默漏掉。用户同意跳过后，该试验移入候选区并注明“未找到可用来源”，标记中的选中数与候选数相应调整。
- 同一链接覆盖多个选中试验时按 canonical source 去重，只提取一次，并在行中保留全部选中试验代码。
- 来源检索完成前不得调用提取、验证或索引。

### 4. 合并或保存可续跑 plan

按输入契约先确定 `{plan_path}`，再检查该路径：

1. 不存在时，创建带头部、`待检索` 标记和候选区的 plan，再写入主表。
2. 已存在时视为未完成任务并续跑。读取旧 plan，以 canonical source 为键合并；保留旧行及人工编辑，只追加新来源，并为同一来源补齐空字段。不得截断、重建、覆盖，或用 `_2`、时间戳、随机后缀绕过碰撞；唯一例外是 4.1 把未选试验移出主表。
3. 同一来源的非空字段冲突、一个来源有多行且无法安全合并，或文件不是可识别 plan 时，停止并列出歧义，交人工处理。
4. 头部只有 `待检索` 标记时：按本次选择整理主表。主表已有行的全部试验 ID 都不在选择中时，移入候选区并保留原 URL、阶段、截止日与备注；行内部分试验被选中时保留该行，只统计选中试验，并在备注注明该来源还覆盖未选试验；试验 ID 为 `—` 的行保留并交人工确认。选中的候选条目从候选区移除后写入主表；已提取复用的选中试验也移出候选区，不新增主表行；未选试验保留在候选区。同一试验已在主表有行时不新增第二行：保留旧行，新来源与旧行不同时把完整备选 URL 和差异写入该行备注；本节对同试验单行的限制优先于第 2 条的追加规则。候选区条目保留候选编号、试验 ID、适应症/线、阶段、最近公开年月和未选原因；来源级候选另保留 URL 和备注。
5. 头部已是 `已确认` 标记时：与主表和候选区已有试验去重，只把新发现的试验追加到候选区，不重复询问用户，也不改动主表已有行。
6. 若本次进入上述选择整理（头部为 `待检索`），整理完成后把标记改写为 `> 临床选择: 已确认 {YYYY-MM-DD}（{自动全选|用户选择} X 个 / 候选 Y；已选: {试验 ID 列表}）`。仍有未解决试验时保持 `待检索` 并停止。无 `临床选择` 标记的旧 plan 不在本步写标记，留给 5.2 完成选择。

plan 主表没有可处理来源时，不进入第 5 步；仅候选区还有未选试验时，报告无待处理来源并结束本次恢复。

#### 4.1 候选项提升

用户要求把候选提升为正式行时：

- 候选临床试验：以 `resolve` 模式只为该试验检索来源，写入主表后从候选区删除该条目，并把 `已确认` 标记的选择方式改为“用户选择”，同步更新计数与 ID 列表。
- 候选来源：把该 URL 行从候选区移入主表，按第 5 步检查进度。
- 无 `临床选择` 标记的旧 plan 先按 3.2 完成选择，再执行提升。

### 5. 检查进度并精确恢复

#### 5.1 检查

运行输入契约中的绝对命令。脚本按当前药品检查 raw/summary、完整审核门禁、药品页、全部应建适应症页和根索引，并输出：

```text
plan 表进度：
- {url}: 已完成 / 已验证未索引 / 未提取 / 已提取未生成summary / 未审核 / 来源对应多个raw / 一个raw对应多个summary / summary文件名不匹配
```

#### 5.2 选择确认门禁

- `已确认`：跳过本节。
- `待检索`：跳过本节和 3.2，按标记中的试验 ID 重新执行 3.3，完成后回到第 4 步整理主表。
- 缺少任何 `临床选择` 标记（旧 plan 或流程中断）时，用 plan 主表已有试验及候选区试验生成编号清单，按 3.2 的同一规则处理：1–5 个自动全选，6 个及以上等待用户多选；写入 `待检索` 后执行 3.3，完成后回到第 4 步整理主表并写入 `已确认` 标记。
- 交互分支未收到有效选择前，不执行恢复或提取；自动全选分支按 3.2 直接继续。
- 候选区不参与进度检查、恢复与重试。

#### 5.3 告知待恢复来源

按规范状态表列出所有需自动恢复的行及动作（已按 5.2 挑选后的主表行；候选区行不列入），必须完整输出为用户可见 Markdown 表格，不得只给概要或省略行：

```text
本次将入库以下数据来源：
| # | 临床代码或NCT编号 | 适应症 | 临床阶段 | 来源类型 | 数据截止日 | 网址链接 | 备注 |
|---|------------------|--------|---------|---------|-----------|---------|------|
| ...（待自动恢复的行，完整列出；另附当前状态与恢复动作）... |

共 N 个来源待处理。将按当前状态自动恢复；如需增删来源可随时告知。
```

这是纯告知，输出后不暂停。全部行均 `fully indexed` 时展示“本次无待恢复数据来源”，跳过恢复并进入第 6 步。

#### 5.4 恢复

按唯一规范状态表分组执行精确动作。所有子 skill 接收完整 identity/path context 原对象。收集每项 raw/summary、审核门禁、药品页、逐适应症页和根索引结果；任何已有文件不得因续跑被覆盖。multi-extractor 返回 `无数据跳过` 的来源：主表行移入 `## 候选（未入库）` 区块，行尾注明“无临床数据，已跳过”，不重试、不计失败。clinical-indexer 必须返回 `drug_page`、`indication_pages`、`root_index` 三项状态；三项均完成后才将该项视为 fully indexed。

### 6. 复查与单次重试

再次运行第 5.1 节的同一绝对路径命令，并重新检查全部索引维度。仍可自动恢复的项先展示当前状态及规范表中的动作，再按该表“第 2 轮重试”列精确重试一次；不得把所有未完成行整体送回 `multi-extractor`。

```text
第 2 轮复查：以下来源仍未完成，将按状态重试：
```

### 7. 汇总

汇总身份、管线、plan、提取、审核、全部索引维度、人工复核和失败项，按输出契约返回。

## 失败与恢复

- 身份无法确认：停下询问，不继续。
- plan 为空：停下询问，不执行提取。
- plan 合并、来源配对、路径或索引目标有歧义：保留文件和产物，列出冲突，交人工处理。
- 数据完整性错误：保留 plan，报告损坏文件，不以重新抓取掩盖损坏。
- 自动恢复第二次仍失败：不覆盖已有产物，不再重试；保留 plan 并写入最终失败项。
- 下次运行读取确定性 plan，以 canonical source 合并最新搜索结果，再从脚本报告的持久状态继续。
